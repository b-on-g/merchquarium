# PRD: Каталог мерча

## 1. Цель

Простой онлайн-каталог мерча художницы: коврики для мыши, пеналы, игрушка-кисточник и другие изделия . Покупатель смотрит товары и одной кнопкой начинает диалог в Telegram. Владельцы (автор и её муж) сами добавляют, правят и убирают товары прямо в каталоге, без отдельной админ-панели и без помощи разработчика.

Первая версия решает одну задачу: показать товары и перевести заинтересованного человека в личный диалог. Оплаты, корзины и учёта в версии 1 нет.

## 2. Пользователи и роли

- **Посетитель** (без входа): видит каталог, фильтрует по категориям, нажимает «Купить» на карточке.
- **Админ** (вход через аккаунт Гипер Базы): всё то же, плюс редактирование каталога.
  редактирование прямо на странице каталога: в шапке над сеткой кнопка «Add product», которую посетитель не видит. Отдельного окна редактирования нет, поля карточки меняются по клику.
- возможны другие авторы со своими каталогами.

## 3. Технические рамки

- Стек: $mol / MAM, данные в Гипер Базе.
- Хостинг: GitHub Pages (статика, бесплатно).
- Сначала только стандартные компоненты $mol и функциональность. Оформление (красивый дизайн) будет отдельным этапом после того, как всё работает.

## 4. Данные

**Товар** ( ему соотвестует компонент карточка = "card" )

- название (текст)
- цена (число, рубли)
- описание (текст)
- фотографии (несколько, порядок важен, первая является обложкой)
- категория (одна из списка, например «коврики», «пеналы»)
- в наличии (да/нет)

**Категория:** название. Список категорий ведёт админ в настройках (добавить, удалить; при удалении категория стирается у её товаров). В карточке категория выбирается из этого списка. Посетитель в фильтре видит только категории, у которых есть товары в наличии.

Настройки ( иконка в правом верхнем углу )
там поле для ссылки на тг
поле для текста в тг 
там же название каталога (показывается в шапке и во вкладке браузера) и выбор темы оформления,
там же id аккаунта в копируемом блоке, debug-инфо (ранг, кол-во продуктов всего и доступных), выдача прав по id и список категорий.
Настройки видит только админ. Новый человек узнаёт свой id, создав свой каталог или открыв ссылку с настройками, и присылает его админу.

## 5. Функциональные требования

### 5.1 Каталог 

- Главная страница показывает сетку карточек товаров. Карточка: все поля, для админа редактируются по клику, и кнопка «Купить». Клик по самой карточке ничего не делает, покупка только по кнопке.
- Над сеткой табы/фильтр по категориям. Есть вариант «Все».
- 

### 5.2 Корзина

- На карточке кнопка «В корзину», дальше счётчик количества. Покупка оформляется заявкой из корзины, подробно в 8.3.
- Для товара «нет в наличии» кнопка неактивна.

### 5.3 Статус «нет в наличии»

- Посетитель товар не в наличии не видит: карточка скрыта из сетки, а его категория из фильтра.
- Админ видит такую карточку с неактивной кнопкой «Купить» и переключает статус флажком Available на карточке.

### 5.4 Режим админа

Все элементы редактирования видны **только админу**. Посетитель их не видит и не может вызвать.

- **Добавление:** кнопка «Add product» в шапке над сеткой создаёт пустую карточку.
- **Редактирование:** админ может изменить у любого товара цену, фото, описание, название, категорию и статус наличия.
- **Удаление:** специальная кнопка на карточке товара (видна только админу).
- Вход: через аккаунт Гипер Базы .
- **Выдача прав:** админ добавляет права на ленд каталога по id другого аккаунта (id выведен в настройках в копируемом блоке).

## 6. Критерии приёмки версии 1

1. Посетитель без входа видит каталог и может отфильтровать товары по категории.
2. Нажатие «Купить» открывает Telegram с корректным текстом и названием товара.
3. Товар «нет в наличии» посетитель не видит; админ видит его с неактивной кнопкой «Купить».
4. Админ после входа видит кнопку «Add product», редактирование и удаление; без входа их нет.
5. Админ может добавить товар с несколькими фото, изменить его и удалить.
6. Изменения админа видны посетителям после обновления страницы, данные сохраняются между сессиями.
7. Приложение собирается и публикуется на GitHub Pages.

## 7. План после версии 1

### 7.1 Темы как продукт

Ядро каталога одно на всех. Художница заказывает только дизайн: мы делаем его новой темой в `bog/prilavok/theme`, и она сразу становится доступна во всех каталогах в настройках. Тема хранится в ленде каталога, поэтому посетители видят тему, выбранную владелицей.

- Сейчас тема задаёт оттенок, разброс оттенков, скругление и шрифт (`$bog_prilavok_theme`): Sakura, Lavender, Mint, Peach, Sky, Milk, Classic.
- Дальше тема может задавать фон-узор, свой шрифт, форму карточки, рамки фото, иконки, декоративные элементы.
- Код темы не меняет поведение каталога: только стили и токены. Новая тема не требует правок в карточке, сетке и настройках.

### 7.2 Массовое создание товаров из JSON

Художница рассказывает нейросети о своих товарах, нейросеть задаёт уточняющие вопросы и выдаёт JSON. Художница вставляет его в настройках, каталог создаёт карточки. Фото она загружает сама в созданные карточки.

```json
{
	"title": "Nyaftul Kitten Art",
	"categories": [ "Коврики", "Пеналы" ],
	"products": [
		{ "title": "Коврик «Котик»", "price": 1200, "description": "…", "category": "Коврики", "available": true }
	]
}
```

- Готовый промпт для нейросети лежит рядом с полем вставки, кнопкой копируется.
- Перед созданием показывается предпросмотр: сколько товаров и категорий будет добавлено, какие поля не распознаны.
- Неизвестные категории добавляются в список категорий.

### 7.3 SEO

Каталоги всех художниц должны индексироваться поисковиками и обновляться без ручной пересборки.

- Реестр каталогов ведёт сам SEO-сервер: приложение сообщает ему о каталоге (`POST /register`), сервер проверяет, что ленд открытый. Попадёт ли каталог в поиск, решает владелица флажком «Show in search engines», флажок хранится в ленде каталога.
- Рендер на нашем сервере: по адресу каталога отдаётся готовый HTML с названием, товарами, ценами и обложками, плюс `sitemap.xml` по реестру. Данные берутся из Гипер Базы, при изменении ленда страница перерисовывается.
- Мета-теги каталога: title и description из настроек, og:image из обложки первого товара.
- Статический пререндер на GitHub Pages (`mol-prerender-action`) подходит только для основного каталога, для всех каталогов в реальном времени нужен сервер.


### 7.4 Статистика (платная)

Художнице нужны ответы про товары, а не про посещения сайта. Сделка проходит вручную в Telegram, поэтому нажатие «Купить» — начало воронки, итог фиксирует сама художница.

Бесплатно:

- Поле «Счётчик Яндекс Метрики» в настройках. Художница заводит счётчик в своём аккаунте, приложение подгружает его на её каталоге рядом с общим счётчиком. Гостевой доступ к общему счётчику не даём: он открывает статистику всех каталогов.
- Тизер платной статистики: «за неделю 120 просмотров, 9 нажатий „Купить“».

Платно, раздел «Статистика» в настройках:

- Просмотры и нажатия «Купить» по каждому товару: что смотрят, но не покупают (цена, фото), что пора допечатать.
- Отметка «продано» в карточке после сделки: выручка по месяцам и категориям, средний чек, доля нажатий, дошедших до продажи.
- Источники: поиск, Instagram, Telegram, прямые заходы; метки для ссылок вида `?from=insta`, чтобы видеть, какой пост принёс продажи.
- Дни недели и часы заходов, чтобы знать, когда постить.
- Спрос на распроданное: нажатия «Хочу, если будет повтор» по каждому товару из 8.1, чтобы решить, что допечатать.
- Второй шаг: поисковые запросы, по которым находят каталог. SEO-домен наш, у каждого каталога своя страница, запросы берутся из API Search Console и Яндекс Вебмастера.

Устройство:

- Сбор: приложение шлёт на SEO-сервер обезличенные события (открыт каталог, просмотрен товар, нажата «Купить», источник). IP и cookies не храним, только счётчики по дням, поэтому баннер про cookies не нужен.
- Хранение: сервер складывает итоги в отдельный ленд статистики каталога. Пишет только сервер, читает только владелица, графики обновляются вживую через синхронизацию Базы.
- Графики на `$mol_chart` и `$mol_plot_*`.
- Доступ проверяет сервер: код клиента открыт, поэтому право чтения ленда статистики сервер выдаёт только оплатившим.
- Оплата: сначала вручную (владелец сервиса добавляет id художницы в список подписчиков со сроком), потом ЮKassa или Telegram Stars с автопродлением.

Мониторинг сервера: внешняя проверка доступности (UptimeRobot или аналог) по `/robots.txt` и странице каталога с уведомлением в Telegram, `healthcheck` в `docker-compose.yml` для перезапуска зависшего узла.

## 8. Доработки

Сначала делаем бесплатное ядро. Платные надстройки над доработками описаны в разделе 7.

### 8.1 Статус «Закончился» (сделано)

Распроданный товар остаётся в каталоге приглушённым, а не пропадает, как сейчас по 5.3. Это показывает спрос («в прошлый раз разобрали»), сохраняет каталог как портфолио, и старые ссылки из постов не ведут в пустоту.

- Три состояния вместо галочки Available: «в наличии», «закончился» (виден всем приглушённым), «скрыт» (черновик или архив, виден только админу). Сейчас `Available = false` смешивает распроданное с черновиками, при переходе старое `false` становится «скрыт».
- Карточка «закончился»: приглушена целиком, на фото снизу плашка «Товар закончился».
- Вместо «Купить» кнопка «Хочу, если будет повтор». Она открывает соцсеть с готовым сообщением «Хочу {title}, если будет повторный тираж».
- У посетителя распроданные товары стоят в конце списка, у автора остаются на своём месте, чтобы карточка не уезжала из-под руки при смене статуса. К фильтрам добавляется переключатель «Только в наличии».
- SEO: такой товар остаётся на странице каталога с разметкой `OutOfStock`.
- Бесплатно. Платная часть — статистика нажатий «Хочу, если будет повтор» по распроданным товарам (раздел 7.4): художница видит, что допечатать.

Как сделано: поле `Status` у товара (`available`, `sold`, `hidden`), функция `$bog_prilavok_product_status`. Без `Status` статус берётся из старой галочки `Available`. При записи статуса `Available` пишется тоже, чтобы старые версии приложения и SEO-узла не ломались. В VK кнопка «Хочу» сначала копирует сообщение, вторым нажатием открывает группу, как корзина. Импорт превращает `"available": false` в «закончился».

### 8.2 Витрина (сделано)

- Шапка: круглая аватарка, под ней ник (название каталога), рядом облачко «У меня есть» с иконками соцсетей, справа кнопка корзины.
- Аватарка, фон шапки и фон страницы загружаются в настройках, как фото товаров. Свой фон страницы заменяет узор темы, цвета темы остаются.
- Соцсетей несколько: в настройках список ссылок (Telegram, VK, YouTube и другие), одна отмечена «сюда приходят заказы». Иконка определяется по адресу.
- Вид мерча — нынешняя категория: одна на товар, фильтр выпадающим списком «Вид мерча».
- Фандомы — теги: у товара их может быть несколько, фильтр выпадающим списком «Фандомы». Список фандомов ведётся в настройках, как виды мерча.
- На карточке под названием вид и фандомы тегами: `#открытка #млп`. Клик по тегу ставит его в поиск.
- Поиск справа над сеткой: по названию, виду мерча и фандомам.

### 8.3 Корзина и заказ ссылкой (сделано)

- На карточке вместо «Купить» кнопка «Добавить» и «+». Если товар уже в корзине — счётчик количества.
- Корзина хранится в браузере покупателя, отдельно для каждого каталога.
- Страница корзины: фото, название, количество, цена; итог; плашка «Информация на сайте не является публичной офертой. Наличие и стоимость подтверждает художница при оформлении заказа»; кнопка «Отправить заявку».
- Заказ — это ссылка: состав (товары и количество) зашит в адрес `#!catalog=…/order=…`. Отправленный заказ изменить нельзя, передумал — новая ссылка. Сервер и База не нужны. Цены и фото страница заказа берёт из каталога, поэтому подделка цены в ссылке ничего не даёт.
- Сообщение заявки: «Здравствуйте! Хочу заказать 3 товара на 1000 ₽: <ссылка>».
- Telegram: текст подставляется в ссылку. Любая соцсеть, включая Telegram: текст копируется в буфер. Для соцсетей без подстановки (VK) кнопка в два нажатия: «Скопировать заказ» → «✓ Скопировано — открыть VK» с подсказкой вставить сообщение в чат.
- Страница заказа у художницы: фото, количество, итог. Позже на ней кнопка «Отметить проданным» — источник выручки для статистики 7.4.

### 8.4 Регресс-тесты (сделано)

- Весь пользовательский путь — один сценарий `app/app.e2e.test.ts`: шаги идут по порядку и опираются друг на друга. Художница создаёт каталог, настраивает вид, соцсети, виды мерча и фандомы, добавляет и импортирует товары, фильтрует, удаляет с отменой. Посетитель со своим ключом получает каталог, видит только товары в наличии и не видит админских элементов, собирает корзину. Товар заканчивается и выпадает из заказа, художница открывает ссылку заказа, заявка в VK уходит в два нажатия.
- Сценарий запускается, только если отвечает мастер Гипер Базы (в тестах это `localhost:9090`), а в браузере ещё и при `test=1` в адресе. Если мастер молчит, в лог уходит отдельное предупреждение «e2e skipped», и пропуск не выглядит успехом.
- В браузере сценарий работает в настоящем контексте приложения, без тестовых моков Базы: каталог берётся из адреса (`catalog=`), а если его нет, создаётся ключом пользователя и прописывается в адрес. Данные остаются в каталоге, в конце в консоль печатается ссылка. Каждый прогон помечает свои товары, виды мерча и фандомы коротким тегом, поэтому повторный прогон на том же каталоге дописывает данные, а проверки смотрят только на свои. В node сценарий идёт в тестовом контексте и ничего не сохраняет.
- Тесты — действия через методы видов, как действует человек. Чистые функции (заказ, соцсети, темы, разбор импорта, SEO) покрыты отдельными модульными тестами.
